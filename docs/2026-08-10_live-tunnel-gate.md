# Live tunnel release gate

`scripts/test-live-tunnel.sh` is an opt-in release gate for a disposable Linux CI runner. It requires root, the authenticated nine-file OpenSSH bundle already installed under `/opt/warptweet`, the server manifest under `/etc/warptweet`, and the dedicated `warptweet` and `warptweet-sshd` accounts created by `test-server-preflight.sh`. It refuses pre-existing product test state.

The tunnel account uses the literal `*NP*` shadow sentinel. [Pinned OpenSSH 10.4p1 documents](https://github.com/openssh/openssh-portable/blob/V_10_4_P1/sshd.8#L281-L302) this as disabling password authentication on Linux without making the account inaccessible to public-key authentication. Its [account check](https://github.com/openssh/openssh-portable/blob/V_10_4_P1/auth.c#L103-L108) rejects a Linux-locked account when PAM is compiled out. The separate privilege-separation account retains the Linux `!` lock prefix. WarpTweet keeps `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, and `/usr/sbin/nologin`. PAM, Kerberos, and GSSAPI support are absent from the authenticated build rather than disabled through unsupported runtime directives.

The gate creates fresh composite client credentials and host trust only at product-owned fixed paths. It rerenders the one managed authorized key, runs server and client doctor, starts two loopback HTTP endpoints and packaged `sshd`, runs the controller, and compares a deterministic payload received through the local forward.

The rendered server and client policy must remain `RekeyLimit 512M 1h` and `LogLevel VERBOSE`. The test daemon alone receives command-line `RekeyLimit=1K 0` and `LogLevel=DEBUG3`. Supplying both rekey components is required because overriding only the byte count retains the rendered one-hour interval. The controller-only server-log segment must contain exactly one connection and one accepted `ssh-mldsa44-ed25519@openssh.com` user authentication. Every KEX epoch must contain, in order, the exact `mlkem768x25519-sha256` KEX, the composite host-key algorithm, both directional approved ciphers, and one sent and one received `SSH2_MSG_NEWKEYS`. At least two complete epochs are required. This proves that the named OpenSSH algorithms completed initial key exchange and one rekey on the controller connection. It does not independently prove each primitive's internal contribution.

Negative probes require rejection of classical-only KEX, a wrong host pin, an actually offered Ed25519 user key, an unapproved target, reverse forwarding, dynamic forwarding, and TUN forwarding. The Ed25519 probe uses a client configuration that offers only `ssh-ed25519`, then requires sshd's isolated transcript to reject that signature algorithm. The reverse and TUN probes send real `-R` and `-w` requests.

Separate packaged `ssh` invocations express shell-without-command, exec, SFTP subsystem, and SCP-style exec intent. Each gets its own client output and isolated server-log segment. Production `MaxSessions 0` rejects the common SSH session channel before the client can send a shell, exec, or subsystem channel request. The server evidence therefore proves that none can cross the production session-channel boundary, while the distinct command line proves which client mode was attempted. It does not claim request-specific shell, exec, SFTP, or SCP messages appeared on the wire.

Agent and X11 forwarding also depend on an accepted session channel. This gate does not create the additional agent socket or X11 display state needed to emit those request messages, and it does not claim independent live agent-forwarding or X11-forwarding rejection evidence. Their rendered-policy checks remain useful, but the broader release requirement in [2026-08-09_architecture.md](2026-08-09_architecture.md) remains open until a capable isolated request-level test exists.

OpenSSH represents both `-L` and `-D` destination requests as `direct-tcpip`; server `PermitOpen` restricts destinations but cannot identify which listener form created the channel. WarpTweet therefore rejects dynamic-forward input at the controller boundary and separately proves that a raw SOCKS listener cannot reach a live unapproved endpoint. This does not claim that sshd can distinguish SOCKS traffic to the one approved target.

The gate creates `/dev/net/tun` as Linux character device `10:200` when it is absent, normalizes it to root-only mode, and performs a temporary `TUNSETIFF` ioctl before the SSH negative. This is a required capability assertion, not a silent skip. A disposable Docker runner must expose the device and capability, for example with `--device /dev/net/tun --cap-add NET_ADMIN`. A GitHub Ubuntu runner without the kernel device or `CAP_NET_ADMIN` fails before any live evidence is claimed.

Cleanup signals only through Linux pidfds. The helper opens a pidfd first, revalidates the captured `/proc` device, inode, start time, and executable, and then signals that retained process reference. The gate never uses broad deletion. It scans captured top-level output for private-key encodings and does not intentionally print private-key bytes.

All fixed-layout files, generated private keys, runtime evidence, `/dev/net/tun` normalization, and dedicated accounts remain after both successful and failed runs. Disposal of the CI VM or container is the only filesystem and account cleanup. The script is not safe as a reusable installer or as a test on a persistent host.

The staged `make test-openssh-integration` gate checks real composite key generation, SSHSIG, renderers, and `ssh -G`. It does not claim client doctor or fixed-path attestation. Those checks occur only here after installation.
